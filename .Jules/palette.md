## 2024-05-23 - Explicit Form Labeling and Dynamic ARIA in Tables
**Learning:** In complex data tables (like the Products tab) and dynamic forms (like the Settings tab), input elements without explicit, context-aware labels cause significant issues for screen reader users. When multiple identical inputs (e.g., "cost of goods" or "+100 ₽" buttons) exist in a table, they become indistinguishable without dynamic `aria-label`s that reference the specific row's subject (e.g., `product.title`). Furthermore, relying solely on visual proximity for form labels is insufficient; standard form inputs require explicit `htmlFor` and `id` pairing, and helper text must be linked via `aria-describedby` to ensure screen readers announce the full context when the input receives focus.
**Action:** Always pair `<label htmlFor="id">` with `<Input id="id">` for static forms. For inputs and buttons repeated within table rows, use dynamic `aria-label` attributes that include the row identifier (e.g., `aria-label={`Себестоимость для ${product.title}`}`). Link helper text using `aria-describedby`.
