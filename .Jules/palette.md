## 2024-06-02 - Form Input Accessibility
**Learning:** In complex UI structures, inputs frequently miss `id` and `htmlFor` bindings when they are part of dynamic lists or custom layout components (e.g. `shadcn/ui` where `label` and `input` are separated). Additionally, inline form elements without visible labels are common, requiring `aria-label`s to give context for screen reader users, especially when the interaction context relies on table rows (like COGS input). Adding `aria-describedby` provides critical context for fields containing help text.
**Action:** When creating or fixing forms, especially within tables, ensure `label` uses `htmlFor` and `Input` has a matching `id`. If no visual label is present, always add `aria-label`, and use `aria-describedby` when a helper description is available. For dynamic inputs (like per-row inputs), include context (e.g. `product.title`) in the `aria-label`.
