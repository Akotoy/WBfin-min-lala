## 2024-06-08 - Accessible Forms and Data Tables
**Learning:** Found two common accessibility anti-patterns in this React app: 1) forms using custom components like `shadcn/ui` `<Input>` where `<label>` text lacked explicit `htmlFor` bindings to the input's `id`, making it difficult for screen readers to associate the text with the input; 2) complex data tables with interactive elements (like inputs and buttons) repeating per row without dynamic `aria-label`s, which causes ambiguity for assistive tech when users navigate by controls rather than sequentially through the DOM.
**Action:** Always ensure `<label>` has `htmlFor` and `<Input>` has a matching `id` in forms. For repeating interactive elements in data tables (like COGS inputs or inline action buttons per row), always use dynamic `aria-label`s referencing the row's specific context (like the product title). Added context to memory to prevent these issues in the future.
