## 2024-06-11 - Form and Interactive Element Accessibility
**Learning:** In complex data tables (like `ProductsTab`) with repeated interactive elements (such as cogs inputs and price increment buttons), screen readers lack context if `aria-label`s aren't dynamic. Static labels result in "Input, Input, Input" when navigating the table. Additionally, when using `shadcn/ui` form components (`Input`, `Label` directly or via native HTML tags), it's crucial to explicitly link the `<label>` to the `<Input>` using `htmlFor` and `id`, and provide `aria-describedby` when helper text (`<p>`) is present (like in `SettingsTab`).
**Action:** Always verify that every `<Input>` and interactive `<Button>` in a `.map` loop includes a dynamic `aria-label` incorporating the row's context (e.g., \`product.title\`). Ensure all standalone forms meticulously link labels (`htmlFor`) to inputs (`id`) and helper texts (`aria-describedby`) for complete semantic and screen reader context.
